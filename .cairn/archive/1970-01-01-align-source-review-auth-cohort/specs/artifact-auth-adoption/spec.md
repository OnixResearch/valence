# Artifact Auth Adoption

## MODIFIED Requirements

### Requirement: Valence adopts one immutable reviewed source

r[valence.artifact_auth_adoption.source] Valence MUST consume `artifact-auth-core` and `artifact-auth-ed25519` from one immutable reviewed `OnixResearch/onix-artifact` revision with aligned Cargo and Nix identities, exact complete source-workspace and release-profile membership, compatible licensing, and a consumer graph limited to those two authentication packages.

#### Scenario: Current source cohort is admissible

- GIVEN Cargo and Nix resolve the same reviewed immutable revision, its complete source workspace and release profile agree, and authentication entry-point bytes match reviewed identities
- WHEN Valence evaluates dependency admission
- THEN it SHALL admit only the two authentication packages and SHALL reject floating, duplicate, mismatched, sibling-path, graph-widening, byte-drifted, or license-incompatible selections.

### Requirement: Unified Artifact workspace source transport

r[valence.artifact_auth_adoption.radicle_transport] Valence MUST consume the two authentication packages from the exact reviewed unified Artifact revision recorded by its current Cargo/Nix pins and source-admission constants while retaining predecessor source identities and receipts as historical evidence only.

#### Scenario: Inconsistent owner profile blocks admission

- GIVEN the immutable owner manifest and release profile declare different source package sets
- WHEN source admission runs
- THEN it MUST reject the cohort without narrowing validation to consumed sub-crates or importing transfer or binding authority.

### Requirement: Cargo and Nix lock agreement

r[valence.artifact_auth_adoption.lock_agreement] Cargo manifests, `Cargo.lock`, `flake.nix`, and `flake.lock` MUST identify the same unified Artifact repository and reviewed Git revision while preserving the exact Nix content identity and two-package Valence consumer graph.

#### Scenario: Locks are regenerated by their owning tools

- GIVEN a coherent reviewed owner source and regenerated Cargo and Nix locks
- WHEN full-source admission and its positive/negative checks run
- THEN exact repository, revision, package graph, NAR, source-byte, and license identities MUST agree and mismatches MUST fail closed.
